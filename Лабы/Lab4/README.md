## 1. Трассировка цикла суммирования (1–4)
Ниже представлена таблица значений переменных до и после каждой итерации для алгоритма подсчета суммы чисел от 1 до 4.

total_sum = 0

| **Подготовка** | — | — | 0 |
| **Итерация 1** | 1 | 0 | 1 |
| **Итерация 2** | 2 | 1 | 3 |
| **Итерация 3** | 3 | 3 | 6 |

## 2. Теоретические вопросы

### Почему цикл `for i in range(...)` завершится?
Цикл гарантированно завершается, потому что функция `range()` генерирует строго ограниченную, конечную последовательность элементов. На каждом шаге итератор выдает следующее значение. Когда элементы в последовательности заканчиваются, цикл автоматически прекращает свою работу. Внутренняя логика программы не изменяет счетчик вручную, что исключает риск бесконечного зацикливания.

### Почему `range(a, b)` не всегда соответствует условию Задания №1?
1. **Исключение правой границы:** Функция `range(a, b)` работает в полуоткрытом диапазоне `[a, b)`. Это означает, что число `b` никогда не включается в перебор, в то время как по заданию вывод должен быть *включительным*. Для движения вверх необходимо использовать `range(a, b + 1)`.
2. **Направление движения:** Если `a > b` (нужно идти на убывание), стандартный вызов `range(a, b)` вернет пустой диапазон, так как шаг по умолчанию равен `+1`. Чтобы генерировать последовательность по убыванию, требуется явно передать отрицательный шаг и скорректировать границу: `range(a, b - 1, -1)`.

## 3. Дополнительное задание: Проверка простоты чисел

Программа `prime_check.py` проверяет число n ≥ 2 на простоту, перебирая потенциальные делители до тех пор, пока их квадрат не превысит тестируемое число (`divisor * divisor <= n`). 

### Результаты ручной трассировки контрольных чисел:
* **2:** Условие цикла `2 * 2 <= 2` ложно. Цикл не выполняется ни разу. Флаг простоты остается истинным. **Результат: Prime**
* **9:** При `divisor = 3` условие `3 * 3 <= 9` истинно. Проверка `9 % 3 == 0` подтверждает делимость. Цикл прерывается. **Результат: Composite**
* **17:** Проверяются делители 2, 3, 4. Ни один из них не делит 17 без остатка. На значении 5 цикл завершается (`25 > 17`). **Результат: Prime**
* **49:** Делители от 2 до 6 успешно пропускаются. При `divisor = 7` условие `7 * 7 <= 49` выполняется, и остаток `49 % 7 == 0` останавливает программу. **Результат: Composite**

*Оценка сложности:* Алгоритм совершает порядка O(sqrt(n)) проверок делимости в худшем случае. Перевод данной логики в рекурсивную форму без изменения математической сути не сделает алгоритм логарифмическим (O(log n)), а лишь увеличит накладные расходы на стек вызовов.
